# Arm64 optimization plan and implementation record

## Implemented

### Integer FSQ ID cache

The uncached condition performs float32 image preprocessing, SD-VAE encoding,
2x2 pooling, sigmoid, and channel-wise FSQ for every request. The optimized
condition reads the resulting `256 x 4` uint8 ID array and reconstructs the
same learned visual prefix through the saved visual bridge.

- Cache payload: exactly 1,024 bytes per image (`256 * 4` uint8 IDs).
- Cache contents: integer IDs only; no random or unreproducible embeddings.
- Validation: every cache entry is regenerated by the float32 tokenizer and
  checked for exact equality before benchmarking.
- Equivalence: the uncached and cached paths must have identical float32
  visual-prefix digests and generated token IDs.

### CPU execution controls

The benchmark records architecture, operating system, PyTorch version, and
thread count. It exposes a fixed `--threads` setting and explicit `--llm-dtype`
selection so comparisons do not silently change the execution configuration.

### Prewarmed request-path measurement

Model loading is completed before warm-up and timed requests. The benchmark
therefore measures online request work rather than conflating it with base-model
download or process-start time. A thread-count sweep uses the same checkpoint,
images, prompt, generation length, warm-up policy, and exact-equivalence gate
at every thread setting.

## Deferred until measured on the selected Arm64 VM

- Thread-count sweep for tokenizer and decoder workload.
- Arm Performix profiling, followed by one evidence-backed optimization.
- Storage/cache-format comparison only if the 1,024-byte raw-ID cache is not
  sufficient for the selected deployment path.
- Any decoder acceleration requiring a model conversion. It must preserve the
  saved Phase 3 bridge contract and deterministic caption output.

## Non-goals

No change is made to the frozen float32 VAE, FSQ formula, bridge weights,
prompt, decoder parameters, or generation settings. No speedup, power, or
Arm-performance claim is made until a fixed Arm64 benchmark run is recorded.
